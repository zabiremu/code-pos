RESTAURANT POS

Documentation

A Laravel-based point-of-sale system for restaurants and cafes — table management, order taking, kitchen display, billing, reports, and QR-code customer self-ordering.

Overview

Restaurant POS is built for a single branch running dine-in, takeaway, and delivery service. Staff sign in with an account an admin creates for them (there is no public sign-up), and the app is organized around five roles: Admin, Manager, Cashier, Waiter, and Kitchen.

Core workflow: a waiter opens an order against a table, adds items with modifiers, sends it to the kitchen; kitchen staff track it on the Kitchen Display board; a cashier bills it (with tax, service charge, and optional discount) and records payment. Customers can also scan a printed QR code at their table to browse the live menu and submit their own order, with no login required.

Server Requirements

RequirementMinimum

DatabaseMySQL 8.0+ (or MariaDB equivalent)

The built-in installer's Requirements step checks all of the above automatically before letting you continue.

Installation

Option A — Web installer (recommended for shared hosting, no command line)

  1. Upload the contents of the package to your hosting account.
  2. Point your domain's document root at the public/ folder. If your host doesn't let you change the document root, leave the project at the account root — the bundled root-level .htaccess routes requests into public/ automatically.
  3. Visit your domain in a browser. You'll land on the installer's welcome screen.
  4. Requirements — confirms PHP version, required extensions, and folder permissions.
  5. Purchase code — enter your CodeCanyon purchase code and an Envato Personal Token (Account → Settings → API Keys on your Envato profile) so we can verify your license before installing.
  6. Database — enter your MySQL host, port, database name, username, and password. The installer tests the connection, writes your .env, then runs migrations and seeds a demo admin account and sample menu automatically.
  7. Finish — you're shown the demo admin login. Change that password immediately from the Profile page after your first login. The installer locks itself shut after this step (see Troubleshooting if you need to re-run it).

Option B — Command line (for a VPS or local development)

composer install --no-dev --optimize-autoloader
cp .env.example .env
php artisan key:generate
# edit .env with your DB_* values, then:
php artisan migrate --seed
php artisan storage:link
If your package didn't include a pre-built vendor/ folder: the web installer (and the app itself) cannot start until dependencies are installed once, because that's what Laravel boots from. Most CodeCanyon buyers are on shared hosting without SSH/Composer access, so the distributed package should ship with vendor/ already built (composer install --no-dev --optimize-autoloader, run once before packaging). If yours doesn't have it yet and you have no command-line access, ask your host to run the command above for you, or use a local machine with PHP/Composer to build vendor/ and upload it alongside the rest of the files.

Configuration

Everything lives in .env. The most relevant keys:

KeyPurpose
APP_ENV / APP_DEBUGKeep production / false on a live site — debug mode shows visitors stack traces on error pages.
DB_*Your MySQL connection. Set automatically if you used the web installer.
ENVATO_ITEM_ID, ENVATO_PERSONAL_TOKENUsed once during the installer's purchase-code step.
PUSHER_* / VITE_PUSHER_*Optional. Configure a Pusher (or self-hosted Soketi) account for instant, real-time Kitchen Display updates. Leave blank and the KDS board still works — it polls for new tickets every 5 seconds instead.
MAIL_MAILERDefaults to log (no outgoing email is required for the app to function).

Roles & Permissions

Staff accounts are created by an admin or manager from Admin → Staff — there is no public registration page.

Admin

Full access: menu, floors/tables, staff (including managing other admins), reports, and every POS/KDS screen.

Manager

Same day-to-day access as Admin, except cannot create, edit, or remove another Admin account, or edit their own role.

Cashier

Order taking and billing/payment screens.

Waiter

Order taking screens (add items, send to kitchen, view/close orders).

Kitchen

Kitchen Display board only — sees tickets, bumps their status.

Feature Walkthrough

Menu & Floor Management

Build nested categories, menu items with optional per-item tax-rate overrides, variants (e.g. sizes), modifier groups (e.g. toppings, required or optional), and an ingredient list per item for automatic stock deduction.

Screenshot: Admin → Menu Items screen

Order Taking

Open an order against a table (or mark it takeaway/delivery), add items with quantity/notes/modifiers, and send the whole order to the kitchen in one action. Each line item then moves through pending → sent → preparing → ready → served.

Screenshot: Order screen with items and status badges

Kitchen Display System (KDS)

A station-filterable ticket board. Kitchen staff bump an item's status as they work on it; the POS side reflects the change automatically (live if Pusher/Soketi is configured, or within 5 seconds via polling otherwise).

Screenshot: KDS ticket board

Billing

Generate a bill for all or a subset of an order's items (split billing), apply a percent or fixed discount, add a service-charge percentage, and record one or more payments (cash, card, mobile wallet, other) — the bill's status updates to paid/partially paid automatically as payments come in.

Screenshot: Bill / payment screen

Reports

Daily sales with top-selling items, low-stock ingredient alerts, and a dashboard summarizing today's orders and revenue at a glance.

QR Self-Ordering

Every table gets a unique, non-guessable link. Print it from Admin → Tables → QR and place it on the table. A customer scans it, browses the live menu with no login, and submits a cart — it lands as pending items on that table's order exactly as if a waiter had entered them, so staff still review and send everything to the kitchen from the normal POS screen. The public menu route is rate-limited against abuse.

Screenshot: customer-facing QR ordering menu (on a phone)

Updating

Back up your database and .env before updating. Replace the application files with the new version (keeping your .env and, if you customized them, your storage/ uploads), then run:

composer install --no-dev --optimize-autoloader
php artisan migrate --force

See CHANGELOG.md in the package for what changed in each version.

Troubleshooting

"I need to re-run the installer"

The installer locks itself after a successful run by creating storage/installed.lock. Delete that file to unlock it — only do this on a fresh install, since re-running migrate/seed against a live database is not intended.

"My URLs show /public/ in them"

Point your hosting account's document root at the public/ folder. If your host doesn't allow that, leave the project where it is — the included root .htaccess already redirects transparently, so no further action is needed.

"Kitchen Display doesn't update instantly"

Without Pusher/Soketi configured (PUSHER_* in .env), the board falls back to polling every 5 seconds — this is expected behavior on hosting with no persistent WebSocket support, not a bug.

"A blank page or 500 error on a fresh upload"

This almost always means vendor/ is missing or storage/ / bootstrap/cache aren't writable. See Installation above.

Security Notes

  • Keep APP_DEBUG=false on any live site — this is the default in .env.example.
  • Change the seeded demo admin password (admin@example.com / password) immediately after installing.
  • Login is rate-limited (5 attempts/minute per email+IP) against brute-force attempts.
  • Only an Admin account can create, edit, or remove another Admin account — a Manager cannot escalate their own or anyone else's access.
