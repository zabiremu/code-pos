# Restaurant POS (CodeCanyon Edition)

A Laravel-based Point-of-Sale system built for restaurants and cafes,
targeting submission to Envato CodeCanyon.

**Status:** Phases 1–6 of the build plan are written (schema, roles, menu &
floor management, order taking + KDS, billing, reports/stock, the web
installer, and Envato purchase-code verification). This repo does **not**
yet contain the Laravel framework skeleton or `vendor/` (see Setup below for
why and how to add it). Not execution-tested end to end — see the note at
the bottom of Setup.

Full build plan (feature modules, database schema, architecture, Envato
compliance checklist, installer design, packaging, milestones) lives in the
project's Claude Docs plan.

## Stack
- Laravel 11.x on PHP 8.2+
- MySQL 8 (production) / SQLite is fine for local dev
- Blade + Alpine.js + Tailwind CSS (via Laravel Breeze)
- spatie/laravel-permission (roles), Laravel Sanctum (API auth)
- Laravel Echo + self-hosted Soketi/Pusher for the Kitchen Display System,
  with a polling fallback for shared-hosting installs

## Setup

This repo currently holds only the **application layer** (migrations,
models, controllers, routes, seeders, views) — not the Laravel framework
skeleton itself, since that's generated by Composer rather than hand-written.

```bash
# 1. Scaffold a fresh Laravel 11 app in a temp folder
composer create-project laravel/laravel:^11.0 _skeleton
# 2. Copy the skeleton's framework files into this repo (everything except
#    what this repo already defines: app/, database/migrations,
#    database/seeders, routes/web.php, routes/install.php, resources/views)
rsync -a --ignore-existing _skeleton/ .
rm -rf _skeleton

# 3. Install this project's actual dependencies
composer install

# 4. Auth scaffolding (Blade + Alpine + Tailwind)
composer require laravel/breeze --dev
php artisan breeze:install blade

# 5. Roles package migrations
composer require spatie/laravel-permission
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"

cp .env.example .env
php artisan key:generate
php artisan migrate --seed   # seeds roles, a demo admin, and a sample menu
npm install && npm run build
php artisan serve
```

### Wiring that needs to happen in `bootstrap/app.php` (generated by step 1, not in this repo)

```php
->withMiddleware(function (Middleware $middleware) {
    $middleware->alias([
        'role' => \Spatie\Permission\Middleware\RoleMiddleware::class,
        'redirect.if.installed' => \App\Http\Middleware\RedirectIfInstalled::class,
    ]);
})
->withRouting(
    web: __DIR__.'/../routes/web.php',
    // ...existing lines, then also load the installer:
    then: function () {
        \Illuminate\Support\Facades\Route::middleware('web')
            ->group(base_path('routes/install.php'));
    },
)
```

Also add to `config/services.php` (generated by step 1):

```php
'envato' => [
    'item_id' => env('ENVATO_ITEM_ID'),
],
```

> I couldn't run `composer create-project` or install packages from the
> sandbox this was built in — its network policy blocks Packagist — so
> these steps, and the code itself, are written out carefully (every PHP
> file passes `php -l`) but not yet execution-tested against a real
> `vendor/`. Run through it once end to end and flag anything that doesn't
> line up — the most likely rough edges are the `bootstrap/app.php` wiring
> above and Tailwind/Alpine asset paths from `npm run build`.

## What's here

- `database/migrations/` — full schema: branches, floors, tables, menu
  categories/items/variants/modifiers, ingredients, orders, bills, payments,
  shifts, stock movements, discounts
- `app/Models/` — matching Eloquent models with relationships
- `app/Enums/Role.php`, `database/seeders/RolesAndAdminSeeder.php`,
  `database/seeders/DemoMenuSeeder.php` — the five POS roles, a demo admin,
  and a sample menu/floor plan so a fresh install has something to click
  through immediately
- `app/Http/Controllers/Admin/` — categories, menu items, modifier groups,
  floors, tables, staff, reports (sales + low stock)
- `app/Http/Controllers/POS/` — order taking (`OrderController`,
  `OrderItemController`), billing (`BillController`, `PaymentController`)
- `app/Http/Controllers/KDS/TicketController.php` — kitchen ticket board,
  grouped by station, with `App\Events\OrderItemStatusUpdated` broadcasting
  status changes (polling fallback baked into the view)
- `app/Services/BillingService.php` — bill generation (incl. split billing
  by item), tax/discount/service-charge math, payment recording
- `app/Services/StockService.php` + `app/Observers/OrderItemObserver.php` —
  ingredient stock deducted automatically when an item is marked served
- `app/Http/Controllers/Install/InstallController.php` +
  `app/Services/PurchaseCodeService.php` — the web installer wizard
  (requirements check → purchase code → database → migrate/seed → finish)
- `routes/web.php`, `routes/install.php` — role-gated route groups
- `resources/views/` — admin layout + screens for every module above
